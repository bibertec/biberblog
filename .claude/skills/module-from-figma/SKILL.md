# Module from Figma

Builds **one module per run** from a design. Pages are assembled afterwards with `npm run page:add-module` (or `npm run page:add` with a base page) – not part of this skill.

This skill is part of the biberblog system (`src/system/manifest.json`). Background: `src/system/docs/plop.md` (generators, naming contracts), `src/system/docs/cli.md` ("Non-interactive"), `src/system/docs/architecture.md`.

## 1. Read the design

- **Figma link + Figma MCP tools available** (e.g. `get_design_context`, `get_variable_defs`, `get_screenshot`, `get_metadata`): load structure, sizes, variables and a screenshot of the frame. If the design has a desktop and a mobile frame, load both.
- **No Figma MCP:** ask for a screenshot/PNG (ideally desktop and mobile). Tell the user that sizes and spacing are then estimated. Setup of the Figma MCP server: `src/system/docs/claude-code.md`.
- Code generated by Figma (React/Tailwind) is a reference for structure and values only – never paste it.

## 2. Plan the fields and get them confirmed

Map the design to fields (`ModuleFieldAnswer` in `src/system/cli/types.ts`):

| In the design | Field |
|---|---|
| Short text: eyebrow, headline, button label, name | `EditableText` (a button/link label can get `link` in the markup) |
| Running text, paragraphs, lists | `EditableRichtext` (paragraphs, bold, lists, links – no headings) |
| Repeated elements: cards, team members, FAQ entries | `EditableCollection` with `itemFields` (`EditableText`, `EditableRichtext`, `EditableImage`) and an `EditableText` `titleField`. No nesting. |
| Photo, illustration the customer should replace | `EditableImage` |
| Decoration, icons, dividers, backgrounds | no field – markup only |

- **Image sizes:** `imageWidth`/`imageHeight` = the size rendered in the desktop frame ×2 (retina), rounded to whole pixels. If the mobile frame shows the image with a different aspect ratio, add `imageMobileWidth`/`imageMobileHeight` (mobile size ×2). Image item fields of a collection have no mobile variant.
- **Names:** module name in PascalCase from the frame name (e.g. "Hero / Split" → `HeroSplit`), field names in camelCase. Check that `src/project/components/modules/<Module>/` does not exist yet.
- Show the plan (module name, fields with types, image sizes) and **wait for the user's confirmation** before creating anything.

## 3. Map the design tokens

Tokens live in `src/project/styles/globals.css`: CSS variables in `:root` (`--site-color-*`, `--type-size-*`, `--type-leading-*`) exposed to Tailwind in `@theme inline` (`bg-background`, `text-foreground`, `text-accent`, `text-muted`, `border-border`, `text-sm` … `text-5xl`, `leading-*`, `font-primary`, `font-secondary`).

- Map every Figma color, font size and line height to the closest token. Spacing uses the Tailwind scale (`gap-6`, `py-16`, …).
- If the design clearly needs a token that does not exist (e.g. a second brand color), **propose it** (variable in `:root` + entry in `@theme inline`) and add it only after the user agrees. Otherwise list the deviations.
- No hex values, no arbitrary values (`text-[17px]`), no new CSS files.

## 4. Scaffold

```bash
npm run scaffold -- module:create '<answers-json>'
```

Example:

```json
{
  "moduleName": "HeroSplit",
  "fields": [
    { "fieldName": "eyebrow", "contentType": "EditableText" },
    { "fieldName": "headline", "contentType": "EditableText" },
    { "fieldName": "intro", "contentType": "EditableRichtext" },
    { "fieldName": "image", "contentType": "EditableImage", "imageWidth": 1600, "imageHeight": 1200, "imageMobileWidth": 800, "imageMobileHeight": 1000 },
    {
      "fieldName": "features",
      "contentType": "EditableCollection",
      "titleField": "title",
      "itemFields": [
        { "fieldName": "title", "contentType": "EditableText" },
        { "fieldName": "text", "contentType": "EditableRichtext" },
        { "fieldName": "icon", "contentType": "EditableImage", "imageWidth": 160, "imageHeight": 160 }
      ]
    }
  ]
}
```

If it fails, report the error message (the actions validate names, types and image sizes) and fix the answers – never create module files by hand.

## 5. Write the markup

Edit `src/project/components/modules/<Module>/<Module>.tsx` – and, for collections, the item markup in `CollectionFields.client.tsx`.

- **Keep the generated contracts:** `function <Module>({ id, content })`, the load statements (`loadContentImage`, `loadCollectionImages`) and every generated `<Editable… fieldId={`${id}.<field>`} value={content.<field>} … />` stay as they are. Wrap them in markup and style them via `className`; don't rename, duplicate or remove them. `schema.ts`, `fieldKinds.json` and `imageFieldRegistry.ts` are not edited by hand.
- **Phone-first:** base classes for the phone layout, `md:`/`lg:` for larger screens. The mobile image variant switches below `md`.
- **Semantics:** one `<section>` per module, headings with the right level (`EditableText` renders a `<span>` – wrap it in `<h1>`/`<h2>`), lists as `<ul>`. Only the module that is the page's hero uses `<h1>`, and its image gets `preload` (LCP); other images keep the default lazy loading.
- **Styling:** Tailwind utilities with the tokens from step 3; reuse helpers from `src/project/styles/css-helpers.ts` (e.g. `containerWrapper`).
- **Client boundary:** `<Module>.tsx` stays a Server Component – don't add `'use client'`. `CollectionFields.client.tsx` must keep its `'use client'` directive: it passes functions (`renderItem`, `createItem`) to `EditableCollection`, which only works within a Client Component. Change only the item markup there.
- No request-time APIs (`cookies()`, `headers()`) – pages are static.
- Optional: replace the placeholder texts in `defaultContent.json` with the texts from the design (same keys and types; richtext stays Tiptap JSON).

## 6. Check

```bash
npm run generate -- --check
npm run lint
npm run typecheck
npm run test
```

Fix any failure. Then tell the user what was created (fields, image sizes, token changes) and how to put the module on a page (`npm run page:add-module`, or `npm run page:add` with a base page). If the dev server is running and a browser tool is available, compare the rendered module with the Figma screenshot. Don't commit.
